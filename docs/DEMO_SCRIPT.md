# Veritext Live Demonstration Script

This demo script guides presenters through an end-to-end, 10-minute live demonstration of **Veritext**, highlighting key innovations across plagiarism detection, obfuscation resilience, AI-text interpretability, and tamper-evident cryptographic reports.

---

## Pre-Demo Checklist
1. Ensure the Python virtual environment is activated (`source .venv/bin/activate`).
2. Verify local references and configuration exist in `data/`.
3. Launch the Streamlit application:
   ```bash
   streamlit run src/veritext/ui/app.py
   ```
4. Open your web browser at `http://localhost:8501`.

---

## Act 1: The Interactive Dashboard & Document Ingestion (2 minutes)
- **Action**: Open the Veritext dashboard in the browser. Point out the clean UI, the "Lite Mode" indicator, and the adaptive document profiling metrics.
- **Narrative**:
  > *"Veritext was engineered from the ground up to provide robust academic integrity analysis without requiring expensive cloud subscriptions or sending student intellectual property to third parties."*
- **Action**: Select the sample file `data/eval/documents/copy_11.txt` (a document containing homoglyph obfuscations).
- **Showcase**: Highlight how Veritext instantly identifies Cyrillic homoglyphic lookalikes and zero-width spaces in the **Anomalies Detected** banner.

---

## Act 2: Winnowing Plagiarism & Diff Inspection (2 minutes)
- **Action**: Click **Analyze Document** with Plagiarism Check enabled.
- **Showcase**:
  - Point to the **Overall Similarity Gauge** and the matched source breakdown.
  - Navigate to the **Side-by-Side Diff Inspector**. Show the original submitted passage next to the matched reference source from the reference corpus.
  - Explain the underlying **Winnowing algorithm** (Schleimer et al., 2003): robust k-gram hashing with guaranteed matching bounds.

---

## Act 3: AI Text Detection with Honest Interpretability (2 minutes)
- **Action**: Switch to the **AI Detection** tab. Load `data/eval/documents/ai_01.txt` (or an ESL essay `data/eval/documents/non_native_01.txt`).
- **Showcase**:
  - Show the **Confidence-Calibrated Probability** (e.g., *"AI probability 1.9% (confidence in this estimate: high)"* or *"Insufficient text"* if under 150 words).
  - Emphasize the **Plain-Language Driver Explanations**: rather than a black-box percentage, Veritext reveals *why* a passage was scored (e.g., *"Unusually uniform sentence length cadence"*, *"Elevated frequency of formulaic transitions"*).
  - Reference `docs/ETHICS.md` and explain how conservative thresholds protect non-native (ESL) students from false accusations.

---

## Act 4: Tortured-Phrase Spinner & Integrity Checks (1.5 minutes)
- **Action**: Switch to the **Integrity Checks** tab. Select `data/eval/documents/spin_01.txt`.
- **Showcase**:
  - Point to the flagged phrases: *"counterfeit consciousness"* (artificial intelligence), *"profound learning"* (deep learning), *"arbitrary timberland"* (random forest).
  - Explain the scientific foundation: documented by Cabanac, Labbe & Magazinov (2021) in their investigation of automated translation and synonym-spinning software in predatory literature.

---

## Act 5: Batch Collusion Matrix & MinHash Screening (1.5 minutes)
- **Action**: Open terminal or use the Batch Collusion UI tab:
  ```bash
  veritext batch data/eval/documents/ --threshold 0.25
  ```
- **Showcase**:
  - Show how 128-permutation Carter-Wegman MinHash and Locality-Sensitive Hashing (LSH) screen pairwise candidates with sub-quadratic complexity.
  - View the generated interactive HTML similarity matrix and point out the detected collusion clusters (`sub_01` & `sub_02`, `sub_03` & `sub_04`).

---

## Act 6: Cryptographic Report Sealing & Verification (1 minute)
- **Action**: Generate a sealed JSON report from the UI or CLI:
  ```bash
  veritext report --json data/reports/sample_report.json data/eval/documents/copy_01.txt
  ```
- **Action**: Verify the report seal:
  ```bash
  veritext report verify data/reports/sample_report.json
  ```
  *(Output: `VALID - Cryptographic seal is intact.`)*
- **Action**: Open `data/reports/sample_report.json`, edit a single character (e.g., change `"version": "1.0.0"` to `"version": "1.0.1"`), and re-run verification:
  ```bash
  veritext report verify data/reports/sample_report.json
  ```
  *(Output: `TAMPERED - Content checksum mismatch. Document payload has been modified since it was sealed.`)*
- **Conclusion**:
  > *"Every report generated by Veritext is cryptographically anchored with an HMAC-SHA256 seal, providing undeniable proof of integrity if a report is audited or exported."*
